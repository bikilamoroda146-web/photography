# Admin dashboard prototype

The `/admin` area is a frontend demonstration, not a security boundary. Its simulated administrator session is stored separately from the customer demo session and tagged with an `admin` role; customer sessions are tagged `customer` and the dashboard route guards keep those demo flows separate. The admin demo entry is not authentication: anyone who can access the browser can create or modify browser storage and reach the simulated admin experience. Do not deploy this as authorization: production access control, role assignment, and every administrative API operation must be authenticated and authorized by the backend. Public registration must never grant administrator privileges.

Bookings use the same browser-backed booking service as the customer dashboard, so status updates are visible in both views in the same browser. Services, portfolio entries, contact inquiries, and admin settings are also saved locally for demonstration. Photo metadata is stored in localStorage and uploaded image blobs are stored in IndexedDB; the photo gallery and public portfolio use that same browser-local collection. Browser storage is not durable or synchronized across users, browsers, or devices. Replace these service implementations with authenticated API/database calls for production persistence.

The admin overview is at `/admin`. Booking requests function as the studio's order/session workflow; the `/admin/products` entry manages the existing bookable service catalogue, which is shared with customer booking forms. Customer, booking, photo, portfolio, and settings screens use the existing browser-backed models.

The photo storage adapter in `src/services/photoStorageService.js` separates portfolio metadata from image blobs so it can later be replaced with authenticated API calls and managed cloud image storage. Current uploads are available only in the browser profile where they were added; they are not a backup or a shared server gallery. Inquiry status changes do not send email; connect a backend notification or email integration before offering replies.
